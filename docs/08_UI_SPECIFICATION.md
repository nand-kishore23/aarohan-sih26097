# UI SPECIFICATION

## Design principle

Beneficiary interface = voice-first, low-literacy, minimal text.

Officer interface = analytical, evidence-rich, provenance-visible.

## Screen 1 — Voice Interview

Elements:
- large voice control
- current question
- replay audio
- simple progress
- language indicator
- privacy/provenance indication.

Do not turn the interview into a long form.

## Screen 2 — Profile

Show:
- education
- current livelihood
- interests
- employment preference
- access constraints
- skills.

Each item has provenance.

## Screen 3 — Candidate Pathways

Title:

> Candidate pathways

Never:
> Best careers

Each card:
- qualification/pathway name
- QP code
- NSQF level
- supporting evidence
- skill gaps
- constraints
- source
- evidence status.

Candidate count may be 0–3.

## Screen 4 — Why / Why Not / Stress Test

Sections:
- Why supported
- Missing evidence
- Skill gaps
- Access constraints
- What could prevent this
- scenario stress test.

## Screen 5 — District Intelligence

Show:
- profiles represented
- observed interest
- training capacity
- potential mismatch
- opportunity evidence status
- evidence gaps.

Never show fabricated demand.

## Screen 6 — Evidence Brief

Show:
- district/area
- data period
- observed interest
- capacity
- potential mismatch
- evidence status
- suggested validation
- human review required.

## Provenance UI

Badges:
- 🟢 Source-backed
- 🔵 Self-reported
- 🟣 Derived
- 🟠 Synthetic
- ⚪ Missing

## Synthetic warning

Use explicit copy:

> Synthetic demonstration signal — not a real-world employment indicator.

## Empty state

Use:

> Evidence unavailable.

Not:
> Low opportunity.
